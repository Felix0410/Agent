# 02 · V2 架构蓝图与模块边界

状态：设计建议，待 T00 架构审计与 T02 服务抽象时细化。保持产品中立性，源码不在此规定。

## 1. 两条工作流与一个共享基础

**交互式路径**：原版 Web / API → 原 Query Planner / LangGraph → 共享检索/章节/Artifact/OpenAlex → 证据与引用 → SSE 返回用户。

**任务式路径**：Research Tasks Web / API → 任务领域服务 → 独立 ResearchTaskGraph（规划/发现/分析/报告/审核）→ 同一共享科研服务 → Persist Results / Task Trace → 产物下载与进度。

**知识构建路径**：PDF → 原 Docling/PDFium / Chunker / Artifact → 原 Chunk/Embedding → B01 层级关系 → B02 增强索引（可选）→ B03 检索路由（可选）→ 两条 Agent 路径可使用。

三条链路明确隔离：旧版功能不依赖新节点是否存在，新增链路也不复制原检索的实质实现。

## 3. 关键对象语义（非数据库 DDL）

- **Document**：上传或从合法开放来源取得的原始文档，含源、许可/可访问状态和稳定 ID。
- **Section**：带章节路径、父级、顺序和原文范围的逻辑区域。
- **Evidence**：可直接核验的原文正文或 Artifact，保留原始文本、出处、位置与内容版本。
- **Knowledge View**：用于导航/检索的摘要、关键词、代表问题，与 Evidence 通过关系关联且有版本。
- **ResearchTask**：目标、范围、预算、已选论文、当前状态、运行版本和时间记录。
- **ResearchStep**：步骤 ID、依赖、状态、尝试、错误、输入/输出对象引用、执行轨迹。
- **ResearchFact**：字段类型、值、单位、条件、证据引用、抽取模型与版本、状态（确认/待核对/缺失）。
- **ResearchArtifact**：矩阵、报告和引用列表，含生成版本与被引用的 Facts/Evidence。
- **EvaluationRun**：基准配置、评测版本、样例、金标、运行轨迹、统计结果。

完整键名和关系由 Codex 依据现有 ORM/SQL 和迁移设施决定；不要为了文档规定而修改已经稳定的表结构。

## 4. 状态与恢复设计

建议业务生命周期：
- DRAFT → READY → RUNNING → COMPLETED；
- NEEDS_REVIEW：候选选择或证据不足需要用户介入；
- PAUSED：安全暂停；
- FAILED：已记录失败，可按策略重试；
- CANCELLED：用户取消，后续不再继续执行未批准动作。

状态枚举与迁移规则由 T03 定稿；业务状态、LangGraph Checkpoint 和 MQ 投递状态不能互相替代。长任务通过持久 Run ID / Task ID 重建上下文，恢复从上次**已提交的业务步骤**继续；工具返回超时须能区分“未执行”与“执行结果未知”，消除重复写入风险。外部工具限时、限次、限成本。

## 5. 故障边界与降级

- 原 PDF 解析失败：保留错误与源文件状态，不生成空论文冒充成功。
- L0/L1 Build 失败：保留原 Chunk 可检索，层级路由回退原 Hybrid。
- 上下文索引缺失：降级到原文向量/词法，不强制重建全库。
- OpenAlex/网络失败：已有本地文献仍可研究；说明候选不完整。
- 候选元数据无全文：允许展示发现结果，不允许输出全文级实验事实。
- 抽取单一字段失败：记录缺失，继续其他字段/论文，不填充幻觉。
- 报告生成失败：中间矩阵与事实不丢失，可再次生成。
- MCP 失败：不破坏主体研究任务，缺少代码可用性部分标记不可用。

## 6. 接口与原系统兼容

先依据 T00 调查确定现有可复用服务边界；T02 使用薄 Adapter 提供稳定调用语义。旧问答 Graph 和新任务 Graph 可共享：
论文列表/全文信息、检索/范围、章节目录、Artifact、OpenAlex、入库任务、引用规范化、Embedding/缓存。不得让新任务 Graph 读取旧 Graph 的内存状态或依赖 Prompt 字符串格式。

兼容性目标：保留现有 API 请求和响应约束、已入库数据库、PDF 阅读器和会话数据；若必须更改，用新增字段/新版本或正式迁移，不做静默破坏。

## 7. 安全、许可和可审计

上传文档、网页文本、MCP 返回都是**不可信内容**；只能作为数据，不得覆盖用户指令或触发越权操作。Tool Schema 白名单、权限核查与 scope 在代码层执行。日志仅记录必要摘要/哈希/耗时，不记录 API Key、敏感正文、未授权论文数据。部署前核实外部模型数据处理约束和学术 PDF 的访问许可。

上游基于 MIT 授权，导入时必须保留版权与许可证，同时区分原版功能和二开贡献。

## 8. 不引入的技术

暂不引入第二套 Agent 编排框架、Neo4j、新向量数据库、全新 OCR 引擎、分布式微服务、强化学习或模型微调。优先复用 FastAPI、LangGraph、PostgreSQL/pgvector、RabbitMQ、Redis、React 和 PDF.js。确有实测瓶颈后再提交 ADR 决定是否扩展。
