# 03 · BRAG 式科研知识构建与检索增强

状态：经讨论确定的 B 层增量设计，尚未实现。B = Build 的工程理念；不是宣称复现 Xiaomi Mi-BRAG 源码或训练模型。

## 1. 动机与现状

现有 PaperWeave 已有：Docling/PDFium、Section-aware Chunking、section_path、Table/Figure/Algorithm Artifact、向量+词法+RRF+Rerank、论文知识星图、查询改写及引用审查。这些是 **B 层的基础**，不能重新当作待开发功能。

不足在于：独立的论文级/章节级语义表示与原始证据之间的父子关联尚未统一作为检索导航；Chunk 的主题与上下文不充分时，研究型问题容易漏召回；跨论文比较需要大量低效的证据试探。B 改造以“Build 阶段更高质量的索引单元”为切入口，不取代 Agent 答案生成逻辑。

参考小米技术对 Mi-BRAG 的公开介绍：https://weibo.com/ttarticle/p/show?id=2309405174583971152010 。其思想包括金字塔知识体系、多维语义索引、假设问题、多模态融合与细粒度溯源。我们只采纳可独立验证的应用层机制，非官方实现，非完整复现。

## 2. B01 — Hierarchical Knowledge Builder（必须）

### 目标
在现有索引上增加明确父子层级，允许“论文概览 → 章节定位 → 原文证据”逐层导航，同时保留“指定事实 → 原文直达”。

### 预期结构
- L0 Paper Profile：稳定论文 ID、真实元数据、研究主题、核心方法、实验概览、知识节点版本；原始摘要与模型生成概览应区分。
- L1 Section Profile：章节路径、层级顺序、摘要/主要主题、父论文、对应子证据范围；保留真实章节名及路径，必要时提供精简主题说明。
- L2 Evidence：原文 Chunk、Table/Figure/Algorithm Artifact，保留原文、来源和稳定引用锚点；视觉摘要为派生字段，不能改写实际证据。
- Cross-paper links：已有引用/相似/方法图谱继续独立运行；不自动把每条相似边变成事实关系。

### 不可破坏的约束
- 只用同一现有 PostgreSQL/pgvector 体系，不新建第二个图数据库。
- 上下级关系可增量建立或重建，不要求修改旧 Chunk 主键。
- 原文内容、出处与原版索引保持不变；构建失败允许回退原版检索。
- 模型生成节点明确标记 derived、source、build_version，不能在结果中作为实验结论的唯一证据。
- 章节缺失或格式异常时允许局部降级，标注不完整层级而不是伪造目录。
- 适应文献多种章节风格，避免将 Introduction/Method/Experiments 等固定英文标题当作唯一结构。

### 验收
已入库样本能返回 L0→L1→L2 父子关系与原 Chunk/Artifact ID；章节顺序正确；重复构建幂等；只修改一个论文时不重建无关论文；存在失败注入下不丢旧证据。

## 3. B02 — Contextual & Multi-View Index（必须为基础版；扩展按实验）

### 技术原则
区分 **source_text**（真实证据，不改写）与 **retrieval_text**（检索增强，可再生成）。原版 Chunk 已有章节前缀，必须以它作为对照而非假称是零上下文。

基础索引视角：
1. 原文语义：Evidence + 简短真实章节信息，保留现有 Embedding 路径。
2. 上下文语义：论文主题/章节概况与局部片段组成新的检索文本；信息来自原文、有上限且记录生成来源。
3. 词法维度：标题、方法名称、数据集名称、缩写及关键词，并继续兼容原有词法检索。

实验型索引（默认不全量开启）：少量代表性“片段可回答的问题”作为独立视角；只针对高价值 Method/Experiments/Artifact 试验。无益则不扩大部署。

### 版本与成本
每条派生索引需可区分：source content hash、构建策略版本、模型版本/Embedding 版本、生成时间与失败记录。缓存命中不重复调用模型；某视角失败回退基础索引；提供索引删除、重建及开关。写入不得覆盖原文 Chunk；清理要通过业务索引引用而不是危险的全库清空。

### 质量风险
上下文摘要可能补充原文没有的结论，生成假设问题可能引入幻觉，过长增强文本可能掩盖细节；因此检索阶段只用作候选召回，答案必须在 L2 原文中核验。对生成节点验证覆盖真实标题/方法信息，杜绝错误作者、年份、实验数值。

### 验收
原文与增强文本在存储/响应中可区分；开启/关闭索引得到正确回退；重跑不重复生成；已有检索仍可用；额外成本、索引量、检索时延可记录。

## 4. B03 — Hierarchical Evidence Retrieval（必须）

### 模式路由
- Fact / Targeted：指定论文、章节、表格或具体事实→直接 L2，避免无用的 L0/L1。
- Overview：论文/方法整体问题→L0 论文筛选→L1 章节范围→L2 原文核验。
- Comparative / Deep Research：跨论文问题→L0 候选论文→按每个比较字段定向 L1→L2 补齐必要证据。
- Fallback：层级路由失败/低质量/开关关闭→原 Hybrid/章节/Artifact 路径。

保留现有 Scope Policy，尤其用户限定目标论文、章节和来源时严禁越界；RRF/Rerank 仍用于候选融合/排序，避免不同索引原始分数简单相加。检索应返回路线、证据身份、派生索引身份（如果使用）与原文位置，支持审计。

### 不做
不把所有查询变成长 Planner；不强制从 L0 开始；不为每个层级分别新增一个 Agent；不自动将图谱相似当成论文事实；不引入未知复杂二次向量存储。

### 验收
原版和新路径由配置开关控制；Fact 查询不走完整层级；跨篇比较能找到对应原文；范围限制不破坏；链路成本可见。

## 5. 消融实验（B03 同步交付）

对照版本：E0 原版 Hybrid/原文索引；E1 +B01；E2 +B02；E3 +B03。确保模型、Embedding、语料快照、候选预算等可比；E1 可以仅提供结构能力，若原检索未消费层级信息，质量指标持平是合理结果。

评测集包含：已知论文定位（继承旧数据）、章节定位、图表/算法检索、中文查询英文论文、跨论文多证据问题、相似主题但数字相反的硬负例。指标：Evidence Recall@K、nDCG/MRR、Multi-hop Coverage、引用支撑、P50/P95、Index Build Cost、Storage Growth、失败与回退比例。

规则：如果新方案没有收益，允许关掉某一视角；不要为了简历而伪造“提升 X%”。结构化层级也可以只对 Deep Research 启用。

## 6. 推荐开发顺序

B01 先完成层级数据和引用；B02 只实现最小上下文语义；B03 挂接可切换路由并做消融；假设问题/跨模态扩展必须等实验支持。每个步骤完成后独立回归，不能把 B01–B03 合并为一次难以回滚的重写。

## 7. 与 Deep Research 的关系

Build 负责“如何准备知识”，Retrieval 负责“如何精确取证”，ResearchTaskGraph 负责“如何完成任务”。Deep Research 可使用 B03，也必须允许回退原版 Retrieval；即使新 Build 发生部分失败，也不应阻塞所有研究任务。T05 研究事实是**可验证的研究域字段**，不是 B01 的论文摘要，请勿重复抽取或混用其事实地位。
