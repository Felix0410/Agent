# 09 · 完整验收场景与交付清单

本文件描述最终应该看到什么，以及出现问题时怎样判断失败。**场景与数据均为验收计划，不代表已跑通。**

## 1. 演示原则

“可演示”不等于截图漂亮：必须连接真实论文、真实检索与真实任务状态，能够重复执行，不能使用固定编造的报告或虚假步骤进度。禁止公开用户的私人 PDF、对话、密钥或敏感科研成果。建议准备许可合适的公开测试论文。

每个演示都需保存：输入配置、使用的论文身份、任务 ID、代码 SHA、模型/工具配置、运行结果、已知限制和关键原始证据。

## 2. Demo A — 原版 PaperWeave 全链路回归

流程：批量上传公开 PDF→查看入库进度/必要重试→打开原文→选择片段翻译→添加批注→使用限定章节或图表算法提问→展开引用→查看关系星图→切换历史会话。

验收：旧功能在新库可运行；文献范围与来源正确；失败场景可见。此 Demo 由 T01 建立，T12 完整回归。

## 3. Demo B — BRAG 分层知识检索

流程：选定已有论文→构建 L0/L1/L2→查看论文与章节导航→针对“某篇具体表格数字”直达 L2→针对“几篇方法的共同限制”先 L0/L1 再 L2→关闭 BRAG 开关返回原版检索。

验收：原始 Chunk/Artifact 的身份没丢；增强检索结果能回到原文；没有跨范围串文档；B02 增强文本不被当作原文；展示 E0–E3 消融的真实指标与成本。

## 4. Demo C — Deep Research 最小闭环

输入：明确的 3 篇已入库论文 + 研究问题（可从现有 RRT/路径规划库挑选）。流程：创建研究任务→确认论文→检索证据→逐篇概况→汇总摘要→保存 Markdown 报告→刷新任务页面重新查看结果。

验收：报告中的核心研究事实有可定位的原文片段；若删掉原文来源，系统不继续编造；状态持久化。这是 T04 的必交演示。

## 5. Demo D — 结构化跨论文比较

输入：3–5 篇同领域可公开论文，指定架构、训练集、实验指标等字段。流程：字段抽取→用户查看事实和证据→生成矩阵→可比性审查→导出研究报告。

验收：各字段保留证据 ID、unknown 状态正确，若两项 PSNR 评测集/协议不同，不直接给排行榜或统计“绝对胜出”。报告可以重现。这是 T06 的主验收。

## 6. Demo E — 自主文献发现与人工审批

输入：研究主题 + 时间范围 + 论文上限 + 是否开放外部源。流程：本地/OpenAlex 检索→候选去重→标记全文状态→用户确认→已有研究链路→报告。

验收：仅有 OpenAlex 标题/摘要时不会生成论文实验细节；能区分候选/已选/拒绝；超时与工具不可用被披露。

## 7. Demo F — 长任务故障恢复

输入：多篇论文比较任务。中途模拟 Worker/API 退出、工具超时、重复触发或取消。流程：记录中间事实与 Checkpoint→重启→恢复→验证无重复报告/记录。

验收：任务状态和持久产物一致；取消后不继续未批准动作；至少一项故障注入复跑可见。T08 完成。

## 8. Demo G — Agent Eval / Trace

从固定 Golden Tasks 执行两个真实版本或两个配置；展示检索、字段抽取、证据支持、任务成功、延迟/成本差异及至少一条失败原因。重点不是“更高分”而是评分可追溯与比较公平。不能把问答路由 100% 合同误称科学正确率。

## 9. Demo H — GitHub MCP（若 T11 已完成）

读取一篇论文可信引用的官方 GitHub 仓库，展示 README 和代码可获得性；再模拟 GitHub 工具不可用，报告主体应继续并标记外部代码部分未验证。仅只读，不执行陌生代码。

## 10. 发布门槛

| 维度 | 最低发布条件 |
| --- | --- |
| 原版兼容 | Demo A 可复现，关键旧测试无新引入失败 |
| 业务完整 | Demo C + D 成功，任务产物真实保存 |
| BRAG 证明 | Demo B 可关闭/回滚，有 E0–E3 公平对照（提升并非强制） |
| 来源可信 | 关键研究事实可定位原文；元数据/生成内容不冒充论文证据 |
| 可靠性 | Demo F 有可复现的恢复、取消、重复运行验证 |
| 评测 | Demo G 有固定样本、金标或明确契约、真实运行结果 |
| 安全 | 不提交密钥、用户私有 PDF/数据库；外部内容不触发越权操作 |
| 文档 | 部署、设计、已完成/未完成、许可证、评测与原版归属可读 |
| MCP | T11 为第二优先级；若延后需明确显示 Deferred，不得假称完成 |

## 11. 演示失败处理

每个 Demo 应有自己的输入、成功条件、失败分类和对应测试。遇到失败先查关联任务包，修复该包后重新跑回归。若 B02/B03 效果不佳，可关闭增强索引，但保留负结果和回退证明；若外部工具不可达，应说明已降级而不是虚构成功。

## 12. 简历/面试叙述规范

说明上游 PaperWeave 已有的 RAG、PDF 阅读与图谱能力，以及本次二开的 Build、ResearchTaskGraph、结构化科研事实、长任务、MCP 和任务 Eval。每个数量和提升必须能指向日志/数据集/提交，不能把上游历史统计当作个人实验结果。
