# 05 · 自动化测试、Agent 评测和验收标准

本文不包含任何已经测得的成绩。所有样本数量都是开发目标，指标只允许来自未来真实运行的结果。

## 一、测试层级

L0 静态检查：格式、类型、基础安全扫描和密钥泄露排查。
L1 单元测试：模型/工具 Mock、状态机、目录安全、Reducer、Skill Parser、预算策略。
L2 集成测试：FastAPI + SQLite、真实 Checkpointer、Tool Registry、文件服务与事件序列。
L3 E2E：真实模型与真实联网/MCP/文档，按实际可用环境分开运行；人工核对关键输出。
L4 故障注入：重启、并发冲突、取消、外部超时、无效来源、权限拒绝、数据损坏。
L5 任务质量：定版样本 + 审核指标 + 与基础策略对照。

不要把 L1 Mock 全绿称作“Agent 成功完成真实研究”；也不能只凭 E2E 一次成功就认为并发/异常可靠。

## 二、必须维护的测试矩阵

| 对象 | 正常路径 | 边界与故障 |
| --- | --- | --- |
| Agent | 无工具对话、工具循环、合法完成 | LLM 错误、工具参数错误、预算耗尽 |
| Thread | 创建、列表、多轮、恢复 | 不存在、非法 ID、同会话冲突 |
| Run | 创建、RUNNING、正确终态 | 并发、重复取消、孤儿记录 |
| Checkpoint | 写入、加载、进程重启后读取 | 失败、异步兼容、重复检查点 |
| SSE | 开始、增量、终态 | 断线、重复、事件乱序/缺失 |
| Todo | 创建、更新、完成 | 重复更新、并发合并、摘要后丢失 |
| Sub-Agent | 委派、结果合并、并发限制 | 超时、取消、无权工具、未知结果 |
| Tool | 输入验证、正常响应、Trace | 异常、不可信内容、长输出、重试 |
| MCP | 正常连接、合法 Schema | 连接断、鉴权错、服务超时、伪装指令 |
| Skill | 合法 Frontmatter、按需激活 | YAML 错误、权限越界、超长正文 |
| Workspace | 上传、读写、下载、哈希 | ../、符号链接、绝对路径、超额、跨会话 |
| Research | 真实搜索、引证、报告 | 失效 URL、证据不足、子任务失败 |
| RAG | 解析、检索、引用、拒答 | 空/损坏 PDF、错页、旧索引、无命中 |
| Security | 最小权限 | Prompt Injection、秘密/路径泄露 |

每阶段要为该阶段引入的状态/合同补齐测试，再进入下个阶段。出现安全或数据一致性回归必须 BLOCKED。

## 三、Research Eval

设计至少五个固定的研究任务，覆盖：事实归纳、多角度比较、反证、来源冲突和搜索不可达/不足。
每个任务有：目标、范围、必须支持的主张、允许来源类别、引用检查方法、终止条件与人工评分表。
主要指标：
- Task Completion：完成可交付报告且满足必要项的任务比例。
- Citation Validity：报告引用中真实存在且可访问/可定位的来源比例。
- Claim Support：人工核查陈述是否由对应来源支持；与仅 URL 可访问区分。
- Coverage：应覆盖的议题中有证据的占比。
- Hallucination/Unsupported Claim：没有证据但被确定性表述的案例数。
- 成本：模型 Token、实际 API 成本、工具次数、墙钟时间。
- Failure Quality：工具失败时能否说明不足而非虚构完整结论。

报告记下原始样本、目标定义、人工核验者和不确定项，不能用模型自己打高分代替人工真值。

## 四、文档 RAG Eval

建立至少十道从原文可核实的 QA/检索题，必须保存标准 Document/Chunk/页码或人工证据定位。
分离两个层面：
检索：Hit@K / Recall@K、正确页码召回、平均检索时间、索引成本。
生成：引用准确率、回答支持率、缺证拒答正确率、回答延迟与 Token。
必须有基础向量检索 Baseline；如果新增 Hybrid/Rerank/上下文增强，则用相同数据和样本做消融。指标无提升也如实记录，不要硬加复杂机制。

## 五、文件工作流 Eval

任务定义应可检查：例如输入两个 CSV，输出一个报告及汇总 CSV，文件名/总行数/统计值由确定性脚本核对。
指标：产物存在率、格式正确率、数值/字段准确率、无效写入阻断率、任务耗时与失败恢复正确率。
对 AI 输出“文件已生成”但实际文件不存在的情况判失败。

## 六、运行可靠性和安全故障注入

必须演示：
- 模型在任务中间断连/限流，Run 不假成功；
- 两个同 Thread Run 冲突并被安全处理；
- SSE 断开后后端任务继续或明确取消语义；
- Sub-Agent 超时与取消，父状态不误判；
- 服务重启后孤儿 Run 识别、Checkpoint 可读取；
- 外部副作用未知结果不被盲目重试；
- 文件路径穿越与符号链接逃逸被阻断；
- MCP/网页返回的恶意 Prompt 不提升系统权限；
- 超长工具输出被预算策略裁剪且有可检索原文；
- 上下文摘要后关键任务和来源引用仍保留。

通过故障测试只证明测试覆盖场景，不等于所有外部服务有严格 Exactly-Once 语义。

## 七、性能与预算记录

统一快照字段：git_sha、环境、测试日期、数据集版本、Prompt/Skill 版本、模型供应商和模型 ID、Temperature/Thinking 等配置、工具版本、索引版本、预算限制。
统计 P50/P95 时必须注明样本量，极小数据不要滥用统计指标。
若对比多个策略，至少固定任务集和模型配置；不同配置需说明差异，避免不公平比较。
所有运行日志脱敏，禁止上传密钥、私有文档全文和敏感用户资料。

## 八、最终验收门槛

1. 干净环境可按文档安装和启动，主要 API/前端与实际代码一致。
2. 三条业务 Demo 均来自真实运行，产物可打开且引用能够定位真实来源。
3. 子 Agent 并发与工具使用有日志/Trace，取消、错误状态可复现。
4. Context 和 Checkpoint 行为有测试证据，明确“能恢复什么、不能恢复什么”。
5. 敏感信息没有进入 Git，文件操作具备越权防护，宿主机 Shell 默认关闭。
6. Eval 有可重复样本、脚本、结果以及失败案例，不引用上游数字冒充自己成绩。
7. README、源码归属、技术架构、Git SHA、变更日志完整。
