## 二、核心架构决策（已批准）

### ADR-001：保留底座，独立新增 Research Agent
- **决定**：复用原有解析、存储、检索、PDF 阅读与可视化，新增独立任务 Graph。
- **原因**：旧 Agent/Planner 较庞大，直接叠加会提高耦合；完全重写会重复大量成熟能力。
- **后果**：需要 T02 稳定适配层；旧问答与新任务并行存在。

### ADR-002：BRAG 采取可切换的 Build 增强
- **决定**：B01/B02/B03 独立开发；L0/L1 为导航，L2 为原文证据；上下文检索文本与原文分离。
- **原因**：现有章节切块已成熟，新的价值是多尺度语义结构与可验证检索收益。
- **后果**：需要版本/缓存、回退和 E0–E3 消融；无收益的视角可以关闭。

### ADR-003：产品只做科研场景
- **决定**：用户价值是论文精读、文献发现、结构化对比、研究报告。
- **排除**：个人秘书、合同审查、邮件/日历、Coding Agent、训练模型等不相关需求。
- **原因**：研究任务闭环更可展示、更可评测，减少范围失控。

### ADR-004：先单 Agent 任务编排，不预置多 Agent
- **决定**：以独立 LangGraph 任务和可复用工具为主，必要时才引入并行专用分析单元。
- **原因**：多 Agent 不保证更准确，增加协调与故障成本。
- **后果**：不为技术简历强行创建无业务必要的 Agent 角色。

### ADR-005：原文证据优于模型摘要
- **决定**：所有重要科研事实需要可核验的原文；外部仅元数据的论文不能提供全文级分析。
- **原因**：降低幻觉和错误实验结论。
- **后果**：输出支持 missing/unverified/incomparable，而不是假定每个字段可填。

### ADR-006：以真实任务评测决定优化是否保留
- **决定**：保留旧检索 Baseline；知识构建做消融；任务做金标、Trace、故障注入。
- **原因**：效果与成本必须有证据。
- **后果**：不把 Hit@K、流程契约或模型自评当作研究任务完成率。

### ADR-007：MCP 是工具扩展，不是架构中心
- **决定**：先接入 GitHub MCP Client，只读验证论文代码相关信息；Server 可选。
- **原因**：有实际科研价值，又避免把全部内部工具都改成 RPC。
- **后果**：MCP 错误可以降级；主体研究不能被其可用性绑死。

### ADR-008：原版来源及二开贡献必须清晰
- **决定**：上游 MIT/版权、来源 SHA、继承能力保留；本次贡献只陈述实际完成内容。
- **原因**：合规、可复现与简历诚信。
- **后果**：T00/T01 必须审查迁移与署名。
