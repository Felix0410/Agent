# 01 · PaperWeave Research Agent 全功能产品与技术方案（最终设计 V2.0）

状态：**目标全量功能说明**。本文兼顾 PaperWeave 原版功能（现有 / 需本地复核）与 V2 增量功能（规划 / 待开发），不是上线公告。技术路线指职责与实现机制，**不锁死具体类名、文件位置、数据库表名和接口路径**；Codex 根据实际源码确定实现。

## 1. 产品定位与交付边界

PaperWeave Research Agent 是面向个人研究者的论文知识空间、精读和自主研究任务平台。典型用户可以积累论文库，查询论文内容，查看图表与算法依据，建立研究关系认知；V2 进一步围绕科研目标自动执行文献发现、候选筛选、多论文事实抽取、比较、证据审核与研究报告生成。

两条产品路径必须并存：
- **交互研究**：原有论文阅读、翻译、批注、检索、问答，讲究低延迟和精确证据。
- **任务研究**：新增 Deep Research，输入研究任务，经历多步骤执行并生成持久化成果，讲究进度、恢复、可解释与可复核。

所有领域事实以论文原文为最终证据。外部元数据只证明元数据字段；模型推断应被明确标为分析意见，不允许装作作者结论。

## 3. 一条完整产品操作旅程

### A. 日常阅读（原版路径）

导入 PDF → 入库队列 → Docling/PDFium 解析 → 章节与 Artifact 构建 → Embedding/检索索引 → PDF.js 阅读/划词翻译/批注 → 单篇或多篇问答 → 来源展示/论文关系星图 → 会话沉淀。

本路径的成功标准是旧功能不退化，新增层级索引不强制替换原检索。

### B. Deep Research（V2 路径）

输入主题或选定库内论文 → 设定范围、数量、研究字段与预算 → Planner 生成研究计划 → 本地/OpenAlex 发现候选 → 候选去重/用户确认 → 获取可访问全文或标记仅元数据 → 检索论文/章节/证据 → 抽取结构化科研事实 → 实验协议可比性核查 → 跨论文综合研究 → 证据审核 → 生成矩阵、Markdown 报告、引用清单 → 持久保存与回放。

任务可在中途展示进度或明确失败。用户确认是长任务的可恢复中断点，不应靠单次 HTTP 长连接维持。

## 4. 主要模块和技术原理

### 4.1 Web / 用户交互

**现有**：React + Vite + PDF.js + Three.js 展示阅读器、知识图谱、问答及入库任务。前端通过 FastAPI 读取会话、文档和流式结果；PDF 阅读与翻译是核心交互特色。

**新增**：Research Tasks 专用入口，展示 Plan、候选论文、选中论文、步骤状态、结构化事实、对比矩阵与报告。进度以服务端持久任务为权威；用户刷新后必须恢复视图。前端不伪造模型调用成功，不以虚拟进度掩盖真实卡住状态。

### 4.2 API 与任务服务

**现有**：FastAPI 负责论文、检索、会话、入库与 SSE。

**新增**：研究任务创建、查看、运行、确认、取消、恢复、导出等业务接口；输入校验、访问范围校验、幂等与状态转移。只定义需要什么能力，不预先锁接口 URL。

### 4.3 Ingestion / 文档与来源

**现有**：Docling、PDFium 回退、RabbitMQ、Metadata、PDF/图片资产持久化、分块、Embedding、pgvector。

**新增 Build**：论文/章节/证据层级节点、指向原文的稳定 Identity；内容哈希与模型/构建版本；原文与生成式增强索引分离；重建不伤害原 chunk；扫描/复杂表格记录质量限制。不要为了统一层级而重新做 PDF 解析器。

### 4.4 Retrieval / Evidence

**现有**：向量、词法、RRF、Rerank、章节和 Artifact、意图/来源约束、Query Rewrite/Retry。

**新增**：按问题粒度动态选择 L0→L1→L2 或 L2 直达；特定目标文件/章节范围不允许被扩大；返回 Evidence Reference（文档、章节、Chunk/Artifact、可用页码与位置、来源类别、原文摘录）；摘要可导航但不可直接证明数值结论。新路径必须可回退原检索并接受消融。

### 4.5 Interactive Agent（保留）

旧 LangGraph 问答工作流负责短问题、精读和多轮讨论，不作为 Deep Research 的内部子图状态直接复用。共享能力通过稳定工具/服务 Adapter 提供，避免直接把旧 Planner 的内部决策状态暴露给新业务。

### 4.6 ResearchTaskGraph（新增）

长期研究任务包含：目标校验、计划/子问题、候选发现/确认、逐篇事实采集、跨篇可比性分析、结论核查、报告生成与交付。节点只保存明确的业务状态与结果标识；支持限次重试、超时、预算、取消、Checkpoint；失败后不重复损坏已完成研究记录。

### 4.7 ResearchFact / 多论文分析（新增）

统一记录“主张/方法/数据集/实验协议/指标/值/条件/来源”，结构化字段可扩展研究领域模板。PSNR 等数值比较必须核对数据集、划分和评价方式；无法确认的一律标记不可比或未知。区别论文直接声称、系统归纳和用户研究假设。数据事实及推断不混存为同一种“确定事实”。

### 4.8 Academic Source / 外部工具

OpenAlex 作为已有的学术发现来源；OpenAlex 元数据不能冒充全论文内容。可配置 Web 来源需保留出处类别。GitHub MCP 是可选只读拓展，用于研究代码公开性与 README 的静态分析，不能自动运行陌生脚本，不能仅凭名称相似认定官方代码。

### 4.9 Memory 与上下文

保留原始消息+会话摘要+可控长期偏好；新增研究任务独立持久化状态、关联论文、选择原因、已验证研究事实、待解决缺口、报告版本。任务记忆不自动写成跨项目“用户事实”；模型生成摘要只是信息压缩，科学证据仍来自论文。

### 4.10 存储与异步工程

PostgreSQL 负责论文元数据/证据、任务/步骤/研究事实/结果及必要 Checkpoint 存储；pgvector 负责向量索引；RabbitMQ 继续处理可重试异步工作；Redis 保留已有缓存和限流用途；Docker Compose 提供本地运行。避免将 MQ 消息、业务状态和 Graph Checkpoint 混同。具体表设计、消息拓扑、迁移机制由 Codex 审计后决定。

### 4.11 Quality / Eval / Trace

旧版保留原入库完整性、来源边界、检索契约和问答审计；新增检索消融、证据召回、字段准确率、实验可比性、引用支持率、任务完成率、故障恢复率、P95 时延和调用成本。Trace 记录步骤与工具状态，敏感密钥和私人论文内容最小化存储。

## 5. 典型任务与输出

**案例 1 — 单篇论文精读**：选原始 PDF，查询某个算法的步骤与表格指标，打开证据、划词翻译并批注。调用原版路径。

**案例 2 — 3 篇本地论文研究分析**：指定 3 个库内 document ID，自动形成方法对比矩阵、实验数据差异与 Markdown 报告。最低稳定演示里程碑。

**案例 3 — 研究主题驱动**：输入近三年某领域轻量模型调研；发现候选→用户确认→合规获取全文→抽取事实→分组对比→输出引用报告。外部全文不可用时只输出元数据层面结论并说明限制。

**案例 4 — GitHub 实现可用性**：对有明确代码链接的论文，用 MCP 读官方仓库 README/配置，记录是否存在权重、训练命令及依赖要求；无官方关系证据时只列候选而不下定论。

## 6. 非功能要求

- **正确性**：证据不足必须说明；检索不到不能生成虚构数值/链接/论文。
- **可恢复**：长任务支持可验证的断点与幂等，外部失败可降级。
- **可观测**：状态、步骤、模型/工具调用、耗时、预算和失败原因能够回放。
- **可部署**：保留原版 Docker Compose 运行能力、配置分层和文档。
- **安全**：工具限权、外部文档视作不可信输入、避免 Prompt Injection 触发越权工具调用；不记录 Key。
- **可扩展**：知识构建与检索扩展由版本/开关控制，避免一次迁移破坏全库。
- **真实性**：所有性能指标都要来自可复现测试，README 区分原版已验证与 V2 目标。
