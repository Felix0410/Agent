# 05 · 科研工具、MCP、记忆与安全边界

状态：规划。原则是给研究任务真实可用的工具能力，不为面试而生造大量插件。

## 1. 现有工具与扩展层

上游已有 LangChain StructuredTool 风格的本地知识库、Vector/Hybrid、Section、Artifact、Document、OpenAlex 和可选 Web 工具，已具备基本 Function Calling。V2 应复用这些服务，提供统一业务 Tool Contract，使研究任务图可组合调用，不直接复制旧图内部状态和检索策略。

一个工具合同必须说明：用途、输入类型/合法范围、输出来源身份、可用性、超时、重试/幂等与错误类别、日志脱敏策略。模型只可选择受授权的工具，不能凭文本虚构执行结果。

## 2. MCP Client（T11 首要落地）

选择 GitHub 作为最小真实 MCP 集成，因为文献经常关联源代码，但不引入完整 Coding Agent。

只读能力：发现可能的论文代码仓库、读取仓库元数据、README、公开复现条件与已存在的官方链接。**官方归属确认规则**：论文、作者官方网站或可信作者元数据显式引用的仓库可标为“有直接归属证据”；仅搜索相似名称返回的仓库只能标“候选”。不执行第三方仓库代码，不拉取私有仓库内容，不对外泄漏身份令牌。

失败策略：MCP 不可达、鉴权失败、速率限制、超时 → 报告代码可用性部分标记 unverified/unavailable；主体论文研究继续，不自动更换成未经授权的来源。

接口隔离：研究图只认识规范化工具结果，MCP transport/server 特有字段限制在 Adapter 内。无需将内部 RAG 函数全部改成网络 MCP。

## 3. MCP Server（可选，不阻塞交付）

只读暴露 PaperWeave 的 search_papers、get_paper_section、get_paper_artifacts 等；必须维持与原检索一致的授权范围、来源披露和限制参数。Server 的开发应以实际外部调用需求为前提，M1/M2/M3 不依赖它。

## 4. Memory：三种不同用途不可混同

- **会话 Memory（旧版已有）**：近期消息、摘要、阶段归档、有限长期用户偏好；供对话体验。长期偏好不是论文事实。
- **Task State / Research Memory（V2 新增）**：任务目标、范围、候选与选中论文、已确认研究事实、证据 ID、当前步骤、失败与报告版本；供断点恢复与跨会话继续。
- **Evidence Knowledge（论文库）**：原 PDF、L0/L1/L2、原始证据、检索索引；不因用户对话内容而改变论文事实。

未经审查的模型猜测不能进入 verified research facts。跨会话时项目记忆只加载任务必需上下文，避免全量拼接所有会话。

## 5. Skills 取舍

不搭建复杂自动生成 Skill 系统。首版只以“研究任务模板”表示 Literature Survey、Paper Comparison 两种模式：规定用户输入约束、研究事实字段模板、所需工具能力和交付格式。模板不是虚假的独立 Agent；未来真实复用需求出现，再评估通用 Skill 注册表。

## 6. 工具可靠性和安全

- **授权**：对上传论文、知识库范围、外部来源和 MCP 都执行实际访问范围检查。
- **输入**：PDF、README、网页等不可信内容严格当作资料，不作为新的系统指令；对“忽略指令、访问密钥”之类 Prompt Injection 不执行。
- **输出**：真实工具返回数据要有 provider、source、timestamp/版本、错误状态；证据不足明确披露。
- **防失控**：调用预算、并行度、超时、重试次数与取消支持；非幂等写操作需设计重复保护。
- **秘密**：凭证通过配置/秘密管理提供，日志、Trace、评测产物不得保存密钥和用户私有数据。
- **成本**：模型和 Embedding 请求记录可统计的 Tokens/费用估计（估计需明确），不泄露 Prompt 原文。

## 7. 测试场景

工具超时、错误 Schema、MCP 不可用、错误权限、重复调用、外部仅返回摘要、相似仓库非官方、Prompt Injection、取消过程中仍有工具调用返回。每种错误都有可观察的任务状态与降级说明。

## 8. 交付界限

T02 建接口；T04/T07 实际工具使用；T08 可靠恢复；T10 Trace；T11 GitHub MCP Client。MCP Server 和大量第三方科研工具在最终核心范围之外，可另开任务。
