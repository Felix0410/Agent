# 00 · V2 产品决策与范围冻结

状态：**已确认的设计目标；尚未开始代码实现**。日期：2026-10-27。

## 1. 项目目标

延续 PaperWeave 的定位：科研论文的长期知识空间、阅读、研究发现与有来源的问答。V2 增加两个有真实业务价值的层次：

- **Build：高质量科研知识构建。** 从 PDF 原文到论文级、章节级、证据级知识节点；允许上下文索引、多路检索与细粒度回溯。
- **Research Agent：可交付的研究任务。** 从研究问题到文献候选、证据获取、研究事实、横向比较与研究报告；记录执行过程，可恢复，可评测。

最终用户是独立研究者、研究生及科研开发者，不是企业办公秘书。核心成功路径为“指定研究主题→搜集/筛选论文→阅读证据→对比→报告”。既有单篇阅读/问答不被新工作流取代。

## 2. 分层范围

**必须交付**：保留原有论文工作台；B01 论文—章节—证据结构；B02 可切换的上下文检索表示；B03 分层检索 + 原版对照；Research Task 创建与运行；3 篇论文的最小研究闭环；结构化研究事实；跨论文比较、可信引用与 Markdown/JSON 导出；外部论文发现（必须区分元数据和全文）；取消/恢复与可追踪结果；固定任务集评测；独立前端入口。

**第二优先级**：GitHub MCP Client，验证论文实现的可用性；暴露只读 PaperWeave MCP Server 可在 Client 验证稳定后酌情做。研究项目记忆仅限任务目标/关联论文/已确认事实/执行历史；Skills 先以固定任务模板表示。

**明确暂缓或不做**：通用办公、邮件/日历、合同分析；复杂自动编码与执行陌生仓库；全能 Coding Agent；大规模多 Agent 自治系统；RL、LoRA/微调、Mi-BRAG 内部模型训练；引入 Neo4j 仅为了画图；新写向量数据库；全领域图谱知识抽取；无限自主联网爬取；海量文档支持的无证据营销承诺。

## 3. 设计原则

1. **先完整主线再复杂策略**：先指定已入库的 2–3 篇论文完成任务，再做自动发现、索引增强和长任务稳定性；任务次序可按依赖调整，但不得突破验收门槛。
2. **旧功能零退化**：通过回归测试证明 PDF 阅读、翻译、图谱、入库、会话与问答正常。
3. **保留真实证据**：生成的 Profile、摘要、问题索引不得冒充原文，数字和结论最终绑定原文。
4. **接口隔离**：新 ResearchTaskGraph 不依赖原问答 Graph 的内部 TypedDict、Prompt 或调试元数据；共享底层检索与入库服务。
5. **可替换与可消融**：增强检索可关闭并回退到原版；各 Build 变体可单独对比。
6. **成本/时延有预算**：工具调用、模型费用、索引费用、重试次数与数据规模必须有上限；长期任务不等于无限执行。
7. **测试先于宣称**：现有文档里的性能是上游历史结果，V2 上线需要自己的运行与人工金标，不将其混为一谈。
8. **代码实现留给 Codex 现场审计**：本套文档定义需求和约束，不固定文件路径、类名、表名和第三方依赖版本。

## 4. 核心业务合同

研究任务可选择两种输入方式：指定库内论文；指定研究主题和筛选条件。输出至少包含：候选论文与理由、已选论文、每篇研究事实与缺失字段、可比性标记、对比矩阵、带证据的报告、执行状态与失败记录。无法获取全文、无法判断实验协议、证据不足时必须明确说明，不得静默编造。

## 5. 版本与验收

- **M0 原版导入与回归**：新仓库有可运行的原版及来源记录。
- **M1 研究任务最小闭环**：指定少量论文，获得有证据的研究报告，独立于旧问答入口。
- **M2 BRAG 与科研分析增强**：分层检索、抽取字段与跨论文对比，经对照评测证明价值；无收益的增强允许关闭。
- **M3 长任务和产品闭环**：自动文献发现、确认、断点恢复、前端和任务级评测。
- **M4 可选 MCP**：真实外部科研工具成功调用并能可靠降级。

每个任务包必须有明确 Git SHA、执行过的测试及真实结果。只有人工审核通过才能更改进度状态为 Done。

## 6. 角色与职责

设计文档是产品目标的唯一规范；Codex 在动手前必须以实际代码核实设计假设，并在实现记录中解释选择。AI 助手负责需求/风险/验收复审，Codex 负责代码、测试、运行、Git 变更。技术决策若发生冲突，以书面 ADR 记录，不悄悄修改目标。
