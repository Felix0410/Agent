# 10 · 上游 PaperWeave 事实基线与差距

截至 2026-10-27 基于上游 README、DESIGN、PROJECT_BRIEF 与关键源码的**静态审查**。此文档不是新仓库功能完成证明，T00/T01 必须本地复查。

上游：https://github.com/zebir-sir/agentic-rag-paper-assistant

## 1. 目前已有的真实产品能力

**论文库与入库**：选择多篇 PDF，顺序管理任务、暂停/恢复/删除；任务经过 RabbitMQ worker；Docling 解析，PDFium 回退；章节感知切块；正文/图/表/算法证据入库；Embedding、PostgreSQL+pgvector；可选图片视觉分析；支持已入库的快速版本向完整证据模式升级；原始 PDF 可回看。

**阅读与知识管理**：React/Vite 工作台；PDF.js 论文阅读器；划词、上下文翻译、术语 Profile 与缓存；批注；本地论文库清单；3D 论文关系星图，关系用于导航，不应成为独立事实证据。

**论文问答与检索**：本地 Hybrid/Vector 检索、章节限定检索、图表算法 Artifact 检索；RRF 融合与文本 Rerank；原版 LangGraph 规划、范围约束、证据筛选、必要时查询改写/重试、答案生成、引用审查；可选 OpenAlex 发现与 Web Search；流式输出、历史会话及取消；区分本地、外部元数据、网页和模型通用知识。

**记忆**：原始消息、会话滚动摘要/历史阶段摘要、有限长期用户画像（高层研究方向与表达偏好、受配置和用户同意约束），并非空白记忆系统。

**工程与评测**：FastAPI/SSE、PostgreSQL/pgvector、Redis（Embedding 缓存/限流支持）、RabbitMQ、Docker Compose、pytest、若干入库/来源/检索/问答契约测试。

## 2. 上游关键技术事实与注意

- 旧 Agent 的核心源码体量较大：agent_langgraph.py、intent_planner.py 为高耦合热点；新业务应建立新图和共享 Adapter，而不是继续堆原文件。
- 原问答 Graph 构建位置直接 graph.compile()，未在该调用点看到持久化 Checkpointer；不等于系统完全没有数据库记忆，更不等于新长任务能自动断点恢复。
- answer_review_runtime.py 在检测到 unsupported_claim_risk 时可能保留回答并记录元数据；不可将其宣传为强事实阻断。
- evidence_support_policy.py 以数字和词面特征做确定性基础检查，不等于已经拥有完整自然语言逻辑蕴含模型。
- 目前项目已有章节元数据、图表证据和上下文前缀，B01/B02 必须在此基础上增强，避免重复实现已存在功能。
- 图谱与研究摘要属于辅助导航/候选发现，不能替代论文实验事实的原文证据。

## 3. 上游公开实验口径（非 V2 结果）

上游 CORPUS_EVALUATION_46.md 报告：46 篇路径规划相关论文、5,467 个检索片段、1,204 个图/表/算法证据片段、已知标题定位 Hybrid Hit@1 91.3%、Hit@5 93.5%。README 另外报告 12 道中文专家金标检索题 Hit@5 100%，100/100 端到端来源/格式契约。

上述结果分别是**已知论文定位、有限查询检索和工作流契约**，不代表开放式问答正确率、Deep Research 研究质量或者“百万文档规模”。真实数字与快照须在 T01 复跑核验，不得直接作为 V2 简历成果。
