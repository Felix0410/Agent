# 04 · Deep Research Agent 业务设计与研究事实协议

状态：V2 核心新产品能力，尚未实现。内容定义用户可观察行为、数据契约、失败边界与交付方式；具体 Graph 节点、模型与 API 由 Codex 按源码决定。

## 1. 研究任务是什么

任务不同于单次问答：有稳定目标、可选输入范围、可执行计划、多步证据采集、人工审查点、可持久化中间结果和最终交付文件。任务不得依赖浏览器或单次 LLM 请求一直保持在线。

**首个 MVP**：用户指定 2–3 篇已经入库的论文和一个研究问题；系统逐篇读取相关原文，生成结构化研究概况，汇总成有证据的 Markdown 研究摘要；结果保存后可再次查看。达到此闭环后再增能力。

## 2. 用户输入协议

必需：研究目标（自然语言）、输入方式（已选论文 或 主题发现）、执行状态身份。

可选：学科/主题、时间范围、论文数量上限、纳入/排除条件、重点研究字段、是否允许外部搜索、是否允许获取公开全文、模型/Token/工具调用预算。参数默认值须保守且可调，禁止无限任务。

工作范围原则：指定库内论文时不得悄悄扩大到其他论文；外部搜索须按用户选择或明确策略开启；论文有 DOI/标题不等于有全文，元数据结论不得代替全文研究。

## 3. 任务步骤与交付

### Stage 1 — Validate & Plan
确认目标、论文范围、预算和字段需求；生成可见的执行计划与子问题。Planning 不是无限自我循环，遇到含糊且关键的任务约束进入 NEEDS_REVIEW。

### Stage 2 — Discover & Select
若为主题模式，组合本地论文与 OpenAlex；通过 DOI、OpenAlex ID、归一化标题合并重复项，保存候选、相关性及理由。支持人工确认。外部 PDF 只通过允许的开放获取渠道取得；单有摘要时保留元数据状态。

### Stage 3 — Evidence Collection
对已选全文论文利用共享 Retrieval 检索论文、章节、表格/算法证据，优先沿明确字段补齐缺失。保留证据 ID、来源、章节、原文摘录及读取时的文档版本。不要把生成摘要当作数值依据。

### Stage 4 — ResearchFact Extraction
每篇论文产出有类型的研究事实对象。见下文科研事实协议。强约束 Structured Output、字段缺失、不确定标记及引用。

### Stage 5 — Comparison & Synthesis
按统一字段对齐论文；检查实验比较成立的前提（数据集版本、划分、数据预处理、指标、数值单位、评价协议）。结论区分“论文报告/系统综合/研究猜想”。不满足可比性条件时禁止简单排名。

### Stage 6 — Evidence Review
检查主要结论是否关联合法 Evidence ID，引用是否来自任务允许范围；重要实验数值原文回查。引用不足的主张重新检索或标记未验证；不许为了完成任务而悄悄删除限制。

### Stage 7 — Deliver
至少输出研究对比矩阵、Markdown 报告、引用清单及生成版本，允许 JSON 结构化产物。PDF 排版不是优先事项；产物可下载/复查，任务重试不覆盖旧完成版本。

## 4. ResearchFact 业务 Schema（概念字段）

| 分类 | 必要语义 | 校验重点 |
| --- | --- | --- |
| Bibliography | title, authors, year, DOI, venue, 文献身份 | 本地/外部元数据冲突与来源 |
| Research Objective | task, motivation, stated_problem | 论文作者直接陈述还是系统概括 |
| Method | architecture, key_components, procedure | 是否真由 Method 段落支持 |
| Data & Training | datasets, split, supervision, augmentation, loss, training_setup | 是否仅论文泛述、是否缺失 |
| Evaluation | dataset, metric, numeric_value, unit, baseline, protocol | 数字、方向、单位、分割一致 |
| Limitations | author_stated_limitations, observed_gaps | 作者所述与系统推断分开 |
| Evidence | document, section, chunk/artifact, snippet, version, source_type | 必须能追到原文 |
| Quality | confidence_label, verified_status, missing_reason, extraction_version | 不允许假设未知变已知 |

真正的数据结构在 T05 经过领域样本审定；允许按领域扩展，不假定所有论文都有训练策略或量化指标。不存在的字段为 missing/unknown，不应填 0、N/A 假数值。

## 5. 对比矩阵规则

矩阵的每个单元格必须可定位到对应事实和证据；可以区分“无报告”“未知”“不可直接比较”“已核验”。实验数值比较必须明确指标越高/越低越好，且数据集、协议等关键条件符合比较要求；未知条件时保守地不给硬排名。

适用于计算机视觉的样例字段：结构类别、轻量程度（有无参数量/FLOPs）、损失、数据集、PSNR/SSIM、推理条件。该模板不强制全学科使用。

## 6. 报告格式

标准研究报告推荐章节：研究目标与检索范围、筛选规则及纳入论文表、方法分类与核心机制、实验设置和可比性声明、对比矩阵、证据支持的发现、作者指出的局限、尚存研究问题（只作为假设）、参考文献和来源/访问限制、模型/工具与执行日志摘要。

对于只返回 OpenAlex 元数据而没有全文的论文，只能在“发现论文”或“元数据背景”部分使用，不能伪装成已阅读其训练或实验章节。

## 7. 任务状态与人机交互

建议 DRAFT / READY / RUNNING / NEEDS_REVIEW / PAUSED / COMPLETED / FAILED / CANCELLED；T03 审计后确定最终枚举及迁移。人工确认候选是正式的可恢复审批点；用户操作要有真实状态反馈。已取消任务不得继续提交未完成产物；失败保留已完成的事实记录和错误摘要。

## 8. 任务记忆与成本预算

任务保存原始目标、子任务状态、已选择文献、证据/事实版本、报告引用、失败与恢复次数、预算与累计消耗。长期会话 Memory 不能代替任务持久化；重复生成同一事实要按文档版本/字段模板/抽取版本缓存和去重。

模型调用、搜索 API 和并行度须设上限；数篇论文并行可作为后续优化，先实现顺序稳定版。

## 9. 最小验收案例

指定 3 篇本地有效论文，以明确主题与字段生成研究摘要和结构化对比；至少有若干条可定位原文的关键论断；模型输出字段与出处符合协议；删掉或无法访问某份论文时记录错误而非假成功；同一任务重试可复用已有中间结果。

## 10. 逐阶段验收

T04 MVP：仅本地指定论文、精简概况、报告，不自动发现；
T05：结构化研究事实；
T06：对比矩阵和规范报告；
T07：自主候选发现与人工确认；
T08：Checkpoint/取消/恢复；
T09：网页工作台；
T10：任务级评测；T11 MCP 为可选增强。

## 11. 不纳入 V2 的能力

独立 Coding Agent、自动执行论文代码、自动训练模型、自动撰写声称原创贡献的论文、无限网络调研、多 Agent 对话模拟。涉及研究假设的建议只是待证实思路，不是已验证科学结论。
