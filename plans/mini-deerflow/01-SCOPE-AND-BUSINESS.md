# 01 · 产品定位、业务边界与优先级

状态：规划，不等于交付。目标：**通用任务型 Agent，而不是只对话的 Chatbot，也不是特定科研系统。**

## 1. 面向谁、解决什么

初期单用户本地或自托管使用。任务往往跨越多个步骤、来源与文件，用户希望获得有依据的最终结果，并能看到执行进度、失败原因及产物。

产品价值：减少人工切换工具、整理资料和生成文档的步骤；能持续追踪同一任务；不是无限自治或无人监管的执行环境。

## 2. 三条代表性业务主线

### A. Deep Research（必须交付）

输入：研究问题、可选范围和目标输出格式。
系统：识别是否复杂任务 → 生成 Todo → 网页检索 → 视情况把子题交给研究 Sub-Agent → 归并证据 → 二次核验 → 报告。
输出：主题摘要、关键结论、来源链接、证据不足声明、Markdown 报告文件。
验收：真实搜索与工具轨迹可查；不能把模型预训练知识伪装为已经查询过的证据；搜索失败可以降级并明确说明。

### B. 文档知识与 RAG（完整产品目标，后于 A 的主链）

输入：PDF/Markdown/文本文件和基于文件的问题。
系统：解析 → 分块/元数据 → 建索引 → 检索与重排 → 带片段来源回答；复杂问题可由 Sub-Agent 辅助分析。
输出：带文档名/位置引用的答案和必要的比较报告。
验收：出处能定位原始内容；无命中时明确不足；区分本地原文与互联网来源。
说明：这需要真实的解析、Embedding、检索服务，不是单独复制 deep-research 的 SKILL.md 就算 RAG。

### C. 多步骤工作空间任务（必须交付基础版）

输入：例如整理多个文件、读取 CSV/Markdown、汇总信息、生成报告。
系统：Plan/Todo → 工具/Skill 选择 → 受控文件操作 → 更新进度 → 保存产物。
输出：文件、汇总和运行日志。
边界：首版只开放安全的文件及数据工具；执行任意 Python/Shell 必须等隔离沙箱通过安全验收。

## 3. 产品能力分级

| 模块 | MVP（先做） | 完整 V1 目标 | V2 可选 |
|---|---|---|---|
| 单 Agent 与工具循环 | 必须 | 稳定 | 多模型优化 |
| 会话 / 流式 API | 必须 | 运行事件与取消 | 多终端 |
| Todo / 动态计划 | 简单版 | 可更新计划、进度事件 | 人工审批节点 |
| Sub-Agent | 暂无 | 独立上下文、并发、汇总 | 持久子任务调度 |
| Tools / MCP | 基础工具 | MCP 白名单与异常隔离 | 动态工具目录 |
| Skills | 暂无 | SKILL.md 按需加载 | 动态安装/市场 |
| Workspace / Files | 基础目录 | 上传、下载、产物、权限 | 容器执行 |
| 上下文压缩 | 暂无 | 预算与摘要 | 长期记忆 |
| Checkpoint | 本地持久化 | 恢复语义/故障处理 | 跨节点 |
| Web UI | 简单操作界面 | 聊天、任务树、文件 | 管理平台 |
| Deep Research | 暂无 | 可引用报告 | 专业研究模板 |
| 文档 RAG | 暂无 | 多文档检索、引用 | 高级索引 |
| Eval / Trace | 关键测试 | 固定任务集、成本、故障测试 | A/B/自动回归平台 |

MVP 是最小技术主线，不宣称已经具备全部业务。完整 V1 是本项目最终求职展示目标；V2 是非必要增强。

## 4. 重要约束

1. **模型驱动的动态执行**：不用固定 Planner→Researcher→Writer 代替所有任务。简单问题直接答，复杂问题再规划/委派。
2. **工具和 Skills 不混淆**：Tool = 能做的操作；MCP = 外部工具接入协议；Skill = 指导任务过程的指令和规范。
3. **父图 Checkpoint ≠ 子任务精确续跑**：只宣称经过故障注入验证过的恢复能力。
4. **用业务驱动技术选型**：初期无 Redis、RabbitMQ、微服务、K8s；单进程/单 Worker + SQLite；必要时再采用 PostgreSQL/pgvector。
5. **可信与安全**：用户上传、网页内容、MCP 结果均视为不可信数据；不允许未确认的高风险写操作。
6. **有量化指标但不预设成绩**：所有性能、成功率、成本必须实际跑测。

## 5. 不在范围内

企业租户/支付/组织权限、邮件日历自动操作、手机端/IM 机器人、自动安装任意插件、无限浏览器操作、多沙箱服务商、RL/微调、全能 Coding Agent、图片视频生成、生产级分布式可靠队列。

## 6. 项目个人贡献重点

优先从三处形成能讲清楚的实现与评测：① 子任务生命周期和可观测执行；② 上下文预算与安全恢复；③ 基于文档的 RAG 引用与评测。它们不是必须同时成为论文创新，只需技术决策真实、代码可解释、测试可重复。
