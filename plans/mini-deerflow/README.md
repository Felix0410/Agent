# Mini DeerFlow：独立新建的通用多智能体任务执行系统

> 状态：总体方案草案 v0.1，供人工审核；截至 2026-11-04 尚未启动代码实现或测试。
> 本文档仅放在 GitHub 隔离规划分支，不改变现有 PaperWeave 项目 main。未来正式开发建议迁移到独立仓库。
> 参考版本：bytedance/deer-flow v2.0.0（tag commit: 7e7f0410797693cf882594555ba414e0361d4c6f）。不 Fork、不继承整仓库源码，而是按模块借鉴，经验证后自主实现。

## 一句话定位

面向个人用户的轻量级通用 Agent：接受复杂任务，决定是否规划、调用工具或委派子 Agent；通过 Skills/MCP 扩展能力，管理运行状态和工作文件，最终交付可追踪的回答与文件产物。

## 目标演示

1. **联网研究**：一个开放主题 → 检索多个来源 → 多轮分析与核查 → 有出处的 Markdown 报告。
2. **文档研究**：上传多份文档 → 解析/建索引 → 跨文档问答 → 引用原文片段；RAG 后期作为独立业务能力接入。
3. **多步骤文件任务**：理解目标 → 制订可更新 Todo → 使用受控文件/数据工具 → 生成交付物，支持取消和故障说明。

## 不做什么

不复制 DeerFlow 所有功能，不自建 LangGraph 框架，不做企业多租户/SSO、IM 多渠道、K8s/分布式沙箱、全能 Coding Agent、未经隔离的自动 Shell、不以 Redis/MQ 堆技术栈。

## 使用规则

规划文档是方向性约束，不声称程序已经实现。先从 P00 建立独立仓库和最小运行基线；每个阶段只实现一条可运行、可测试的完整链路；一次只给 Codex 一个任务包；每阶段必须提交测试结果并由用户审核后推进。源码路径、依赖版本和具体类名属于建议，开发时以实际环境与验证为准。
