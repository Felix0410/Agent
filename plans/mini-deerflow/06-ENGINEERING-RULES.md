# 06 · Codex / 本地 AI 协作、上下文预算与工程规则

## 1. 分工与推进方式

人类：批准范围、评估业务价值、审核阶段和关键安全决策。
本规划/架构助手：给出模块设计、上游对照、任务验收标准并复核 Codex 报告。
Codex/本地 AI：在真实仓库中实现当前任务、写测试、运行、提交并反馈证据。未获得用户同意，不自动开始下一阶段。

## 2. AI 上下文预算（关键原则）

- 每次只读取：项目 README/当前架构摘要、当前任务包、当前模块相关代码、必要测试；避免一上来扫描整个上游 DeerFlow。
- 上游每次只打开 1~3 个直接相关文件，先掌握调用边界和数据结构。确需额外上下文时说明原因，再扩展搜索。
- 新技术先解释 **是什么 / 解决什么问题 / 为什么现在需要 / 核心机制 / 替代方案**，再动代码。
- 以小型接口和明确依赖减少多 AI 重复阅读。单个任务包只改当前所需代码；避免模块无关大重构。
- 每阶段维护简短的 CURRENT_STATE.md（当前可运行能力、入口、接口、测试、已知问题），新 AI 先读此文件。完整历史放 docs/，不每次全部加载。
- 不将大规模真实聊天记录、PDF 正文、完整 Trace 塞进 Agent 系统提示词或 Codex 上下文。

## 3. 每次任务包格式

目标与用户价值；当前最简端到端流程；输入/输出/模块边界；必须遵守的不变量；指定上游源码链接；允许/禁止改动范围；验收案例；测试命令；风险与回退策略。
所有实现后回复包含：变更文件、设计取舍、实际命令/测试结果、失败/未运行项、Commit SHA、下一阶段依赖。不得用未验证的猜测冒充测试。

## 4. 代码要求

- Python 类型标注与 Pydantic；清晰模块边界；可配置模型与 API Key（仅环境变量/私密配置）。
- 小函数、单一职责，优先现有 LangGraph/Tool API，避免造第二套图引擎。
- 每个异步工具有超时；外部请求设次数/速率/Token 预算，避免无限循环。
- 危险外部写操作默认不自动执行；无法确定副作用结果时不盲目重试。
- 并发子任务共享工作空间时须有路径与写入冲突策略；任务数限制可配置。
- Prompt 与返回的网页/MCP/PDF 内容分开，不能把外部内容当作高优先级指令。
- 先保持结构简单；技术债与复杂度放 ADR，不为了“架构好看”引入过多抽象。

## 5. Git / 版本 / 授权

- 开发使用专门独立仓库，当前 planning 分支仅是临时设计文档存放区。
- 阶段小提交，不重写未授权的工作区变更；每次可回滚；保护主分支。
- 固定 DeerFlow 参考 tag/commit；不把上游代码块当作未经归属的原创。
- 复制 MIT 源码时依法保留版权/许可证；引用论文和组件公开链接；简历区分自研部分与参考部分。
- 不提交 .env、Key、真实私人数据、可识别记录、模型响应中的密钥。

## 6. 文档最小集（避免文档泛滥）

- README：如何安装和演示、已实现功能。
- docs/ARCHITECTURE.md：当前真实结构，非未来想象。
- docs/DECISIONS.md：少量关键 ADR。
- docs/CURRENT_STATE.md：给 AI 的高密度当前状态。
- docs/PROGRESS.md：阶段状态、测试和 SHA。
- docs/UPSTREAM_REFERENCES.md：只记真实参考代码及保留理由。
- eval/：评测数据与真实结果。

文档有一个事实来源；不要在多个地方拷贝同一张任务表并产生冲突。

## 7. 代码审核/暂停条件

若出现权限越界、依赖冲突、状态不一致、业务链路失败、明显性能回退、未记录危险修改，直接 BLOCKED；不得自动扩展新功能。所有例外以 ADR 记录并由用户批准。

## 8. 第一条 Codex 任务（P00，不含业务开发）

先检查目标新仓库是否已经创建且为空；核实 Python/Node 环境和锁版本方案，生成轻量骨架、健康测试与基本 CI/本地脚本；确认许可证、开发入口、密钥隔离与文档移动方式。不得克隆整套 DeerFlow 源码进工作仓库，也不得动现有 PaperWeave 项目。
